The three options

Same frontier models. Very different value.

Copilot Fusion doesn't replace Claude Opus 5.5, GPT-6.1 Sol or GPT-6 Astra — it uses them, where each one is best, and adds review only when a task warrants it.

Option A

One fixed model

Developer picks Opus 5.5, GPT-6.1 Sol or GPT-6 Astra — and uses it for everything.

Every prompt→Same model
  • Docstrings billed at frontier rates
  • Manual switching (and forgetting to switch back)
  • No independent review of its own work
  • No discount — standard model rate
Option B · previous default

Auto model selection

Copilot routes each prompt to one best‑fit model, with Efficiency / Balance / Intelligence tiers.

Each prompt→Router→1 model
  • Right-sized model per prompt
  • Health- & cache-aware routing
  • 10% discount on model costs
  • Still one model per prompt — no draft → review → revise
Option C · GA 28 Oct 2026

Copilot Fusion

Routes and orchestrates models per prompt: Single, Cascade or Critique.

Each prompt→Fusion→1…n models
  • Everything Auto does, plus multi-model orchestration
  • Cross-family critics & quality-gated escalation
  • Reasoning effort tuned per step
  • 30% launch discount on model costs*

How Copilot Fusion works

Three execution patterns. Chosen per prompt.

Fusion evaluates each task on reasoning, code generation, debugging and tool-use signals, then picks the least complex workflow that meets the quality bar. Extra model calls happen only when they're likely to improve the result.

Get started in 3 steps

  1. Admins: review which models Fusion may use in enterprise model policies.
  2. Admins: optionally set Copilot Fusion (any effort level) as the default via Enterprise managed settings.
  3. Developers: open the model picker → Copilot Fusion → choose Standard, High or Max.
